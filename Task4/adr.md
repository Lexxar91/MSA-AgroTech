# Рекомендуемое решение

Выбран основной вариант (гибрид edge + cloud) по следующим причинам:

## Полное соответствие требованиям

- Реакция ≤5 сек для всех компонентов (включая облако),
- Работа без интернета с буферизацией событий.

## Высокая бизнес-ценность

- Возможность масштабирования как SaaS-решения,
- Live-дашборды и аналитика в реальном времени — ключевые конкурентные преимущества.

## Управляемые риски

- Зависимость от RabbitMQ компенсируется DLQ и повторной отправкой,
- Использование проверенных паттернов (асинхронные очереди) снижает долгосрочные риски.

## Соответствие уроку «Как выбрать технологию для интеграций»

Для команд и запросов («заполнить кормушку», «отправить алерт») выбран RabbitMQ — как рекомендовано в уроке для сценариев «точка-точка» с умеренной нагрузкой.

# Компромиссы

| Компромисс | Обоснование |
|------------|-------------|
| Сложность реализации | Дополнительное время на настройку RabbitMQ окупается гибкостью и масштабируемостью |
| Зависимость от брокера | Использование DLQ и механизма повторной отправки минимизирует риски потери данных |
| Ресурсы на edge | Docker Compose (с restart: always) позволяет эффективно использовать ресурсы без оркестратора (k8s избыточен для одной фермы) и обеспечивать self-healing |
