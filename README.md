# MSA-AgroTech

## Архитектура MVP системы мониторинга свиноводческих ферм

# 🎯 Цель

Разработать микросервисную архитектуру для автоматизированного мониторинга свиноводческих ферм, которая:

- Обнаруживает драки, задавливание поросят, болезни и гибель в реальном времени,
- Управляет кормушками и поилками разных производителей,
- Работает автономно при отсутствии интернета,
- Поддерживает масштабирование как SaaS-решение.

Система соответствует строгим требованиям:

- Время реакции ≤5 секунд
- Отказоустойчивость ≥99,95%
- Работа в условиях нестабильного интернета

# 🏗️ Архитектурные решения

Проанализировано два варианта:

| Вариант | Описание | Статус |
|---------|----------|--------|
| Гибрид edge + cloud | Локальный edge-агент обрабатывает видео и управляет устройствами. События отправляются в облако через асинхронную очередь (RabbitMQ) с буферизацией при потере связи. | ✅ Выбран |
| Полностью автономный edge | Все решения принимаются локально. Синхронизация с облаком раз в 10 минут. | ❌ Не соответствует требованию «реакция ≤5 сек» для облачного мониторинга/SaaS |

# 🧩 Технологический стек

- Язык: Python (единый стек для всех компонентов)
- Edge: Docker Compose с restart: always (изоляция отказов и self-healing без оркестратора)
- Облако: Kubernetes (масштабирование под 150+ ферм, ReplicaSets)

## Интеграции:

- Синхронные: REST, gRPC
- Асинхронные: RabbitMQ (команды и запросы, точка-точка)

- Хранение файлов: MinIO (S3-совместимое хранилище)
- Диаграммы: PlantUML + C4 Model

# 🗂️ Структура проекта

```text
MSA-AgroTech/
├── Task1/   # Контекстные диаграммы (C1) + ADR
├── Task2/   # Контейнерные диаграммы (C2) + ADR
```

Каждая папка содержит:

- Диаграммы в формате `.puml` (PlantUML),
- ADR в формате Markdown (где требуется).
